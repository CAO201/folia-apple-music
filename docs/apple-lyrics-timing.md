# Apple Music 逐句歌词与时间轴

此功能只更换歌词，不更换 Apple Music 音频，不改写系统“音乐”的歌曲或自定义歌词。

## 来源优先级

1. 已手动确认的歌词或导入文件仍优先保留，清除手动设置后恢复自动来源。
2. 自动匹配先用网易云；检查标题、歌手、录音版本、时长，并最多检查 3 个符合条件的候选。优先逐字，其次逐句。
3. 网易云没有有效时间轴或请求失败时，独立读取 Music.app 资料库歌曲的 `lyrics` 字段。这个字段可能是空的或只有文本，不代表 Apple 云端歌词正文。
4. 简介内容已含有效时间戳时转换为 Folia 的歌词格式；纯文本只进入打点编辑区。

## 使用

在播放器的歌词面板展开“逐句歌词与时间轴”，或在命令面板搜索“逐句打点”。网易云手动匹配窗口也有同名入口，可把候选文本带入打点。

- “读取 Apple 简介歌词”：只读资料库，空值或不可读取时有明确说明。
- 粘贴普通歌词，每句一行；或导入歌词文件。
- “使用文本内的时间轴”：校验 LRC / Apple 格式 TTML / VTT / YRC 的真实时间戳，拒绝无时间轴文本。
- 在 Folia 播放此歌曲，每句开始点击“标记下一句”。聚焦该按钮时可按空格。
- 可撤销，逐句修改开始秒数，或点“试听”跳到已标记的位置。保存要求每句都有时间，且按顺序位于歌曲时长内。末句显示到歌曲结束，不猜测字级时间。
- “匹配当前歌词时间轴”：要求当前播放身份一致、完整句序一致；只忽略标点与规范化差异，不使用模糊匹配或平均分配。
- 草稿和最终选择按 Apple 歌曲身份分开保存；切歌后禁止用新歌进度给旧歌打点。

## 动效与边界

逐句时间轴使用原有歌词引擎。网易云 YRC / 带逐字时间的 TTML 保留对应能力；手动逐句打点不会伪造逐字高亮。

新自动缓存与旧缓存隔离；旧手动绑定保留。历史无时间轴的 TXT 不直接用于动态显示，可重新导入后打点。现有歌词整体偏移设置继续可用，打点记录的是原始播放位置。

## Apple 云端同步歌词研究

官方歌曲 API 文档中的 hasLyrics 只说明歌曲是否有歌词，并不是歌词正文和时间轴。当前未核实适合此免费开源版稳定使用的公开读取路径，因此本版本没有自动获取 Apple 云端 TTML 的能力。不会把社区 TTML 标成 Apple 官方，也不要求用户提供 Apple 密码或私钥。

2026-10-18 本机只读抽样：20 首资料库歌曲的脚本 lyrics 字段均为空。此结果只代表本机样本，不能推断所有歌曲都为空，也不能宣传“每首歌都会自动取得官方歌词”。

参考：[Apple 歌曲属性](https://developer.apple.com/documentation/applemusicapi/songs/attributes-data.dictionary)、[Mac 中查看与输入歌词](https://support.apple.com/en-ca/guide/music/musf438ffc97/mac)。
